# Section VIII. From Vault to Website

Spine for the draft phase. Each H2 has a word budget; subtotal is 700. Each bullet states the claim, names the evidence, and signals the inferential move it carries for the rest of the article. Section VIII is the third section in the IV-V-VIII concrete trio: Section IV inventoried the raw LMS export, Section V described the typed intermediate vault that translates that export, and Section VIII walks the pipeline that publishes the vault as a static site readers actually open. The recurring sentence per L-002 lands at the close of Section VII, not in Section VIII's body, because the VII/VIII seam means the close of VII; Section VIII opens by picking up the thread without restating the sentence. The section's load-bearing inferential payoff is the architectural posture it establishes for Section XII: the case study is a reviewed static site, not a chatbot, and the publication pipeline is the operational proof of that posture.

## 8.1 What the deployed site is (110 words)

- Claim: the vault is published at a public URL, with a fixed-date corpus snapshot of 198 pages (92 case briefs, 27 doctrinal topic pages, 79 lecture summaries), the same snapshot Section IV anchors and Section V's typed-intermediate-layer argument operates on. Evidence: evidence-08-live-deployed-site. Inferential move: the deployed site, not the local vault on disk, is the artifact a student or peer reviewer opens; Section VIII opens by naming the URL and the snapshot so the IV-V-VIII trio triangulates on the same fact without restating counts, and the rest of the section walks the pipeline that produces what the URL serves. [evidence: evidence-08-live-deployed-site]

## 8.2 The build pipeline: markdown to JSON to SPA shell (180 words)

- Claim: the build is one Python script (`.site/build.py`) that walks the three content folders, parses each page's YAML frontmatter, renders the markdown body with `markdown-it`, resolves Obsidian-style wiki-links into in-app hash routes, extracts the structured holding-bar and citation-metadata blocks from each case page, and writes three JSON artifacts (pages.json, manifest.json, search.json) into `.site/dist/`. Evidence: evidence-08-build-pipeline-shape. Inferential move: the production surface is narrow enough that the attorney-author can reason about every step from markdown source to rendered page without a model in the loop, which is the operational basis for the static-versus-chatbot risk argument in Section XII. [evidence: evidence-08-build-pipeline-shape]
- Claim: the runtime shell is three hand-written files (`index.html`, `app.js`, `style.css`) that load the JSON artifacts at runtime, define a hash-route navigation reaching every page through a stable URL, wire a ⌘K search palette to `search.json`, register a Netlify `page-feedback` form stub at build time, and embed PostHog analytics with session recording disabled and Do Not Track respected. Evidence: evidence-08-spa-shell-and-routing. Inferential move: the shell's small surface area is the second operational basis for the Section XII risk argument; analytics and a feedback stub belong to the build artifact, not to a runtime model. [evidence: evidence-08-spa-shell-and-routing]

## 8.3 Deploy as a first-class rotation phase (170 words)

- Claim: deployment is a Netlify CLI direct upload using a gitignored local personal access token (PAT), with the netlify.toml configured to disable post-processing (`skip_processing = true`) and to register a single SPA-style redirect so the artifact uploaded is exactly the artifact served; a three-tier fallback chain (CLI direct upload preferred, Netlify MCP fallback, `.site/deploy.sh` shell wrapper as last resort) keeps deploys reproducible from a scheduled task without leaking credentials and without consuming Netlify build minutes on the preferred path. Evidence: evidence-08-netlify-direct-upload. Inferential move: Section IX's cost-and-labor table inherits the build-minutes-zero claim from this bullet, and PI-018's deploy-phase cost line routes there rather than burdening Section VIII with the full numeric table. [evidence: evidence-08-netlify-direct-upload]
- Claim: deploy is a first-class rotation phase, with its own per-phase rubric, its own pending-issue lifecycle (`applies_to_phase: deploy`), and a cardinal rule that no vault failing Verify is published; a stale live site beats a broken one in front of the professor. Evidence: evidence-08-deploy-as-rotation-phase. Inferential move: this is the architectural pivot Section VIII makes to set up Section XII's risk argument; publication is a phase the system can fail, log, and retry on a defined cadence, not an event that fires whenever a human pushes to a branch. [evidence: evidence-08-deploy-as-rotation-phase]
- Claim: post-deploy verification distinguishes a successful upload from a successful publication via four sub-checks against the production CDN: manifest counts compared against the local build, a deterministically-sampled page-fetch sample (five case briefs plus three topics) that must return HTTP 200 with the expected title in the body, a search-sanity probe confirming the live `search.json` returns *Marbury v. Madison* for the query "judicial review", and a Source Materials HEAD-sample confirming the served PDFs return the correct `Content-Type`; each failure mode opens a typed pending issue and blocks state advance. Evidence: evidence-08-post-deploy-verification. Inferential move: this is the artifact-side complement to Section VII's source-side Verify discipline; Section VII verifies what the vault says, Section VIII verifies what the CDN serves. [evidence: evidence-08-post-deploy-verification]

## 8.4 Auditable inputs and a closed feedback loop (140 words)

- Claim: the deployed site does not only publish the AI-authored briefs; it also serves the professor's original source materials behind direct download links the build emits whenever a page wiki-links to a file under `Source Materials/`, with `_headers` rules giving the source files long-lived caching while keeping the generated JSON artifacts on short TTLs. Evidence: evidence-08-source-materials-served-direct. Inferential move: this is the auditable-input commitment that pairs with the auditable-output commitment of a reviewed static page; a reader can inspect both what the system was given and what it produced, which is the transparency artifact that distinguishes the vault from a chatbot that paraphrases its sources without exposing them. [evidence: evidence-08-source-materials-served-direct]
- Claim: the deployed site is not write-once; every run begins with Step 0, which pulls submissions from the Netlify `page-feedback` form, triages each into the maintenance phase that can fix it (Lint for typos, Enrich for content gaps, Synthesize for new topics, Verify for disputed facts), and either fixes inline or logs a typed pending issue carrying the page ID, page title, submitter identity, verbatim comment, and Netlify submission ID; the scope-selection step of the next-running phase prefers pages with open `professor-feedback` issues routed to that phase. Evidence: evidence-08-feedback-form-loopback. Inferential move: the published site talks back to the vault, and the vault routes the talk-back through the same rotation that produced the page, which is the closed-loop framing Section XIII later picks up for the institutional-implications argument about who owns the course knowledge system over time. [evidence: evidence-08-feedback-form-loopback]

## 8.5 Static site, not chatbot (100 words)

- Claim: Section VIII's most load-bearing claim is the architectural one: the case study is a reviewed static site, not a chatbot; no LLM sits in the request path; the published page is a stable HTML and JSON artifact, written and verified by the rotation phases at publish time and served by the CDN without further model inference; risk lives in the build pipeline where Verify can catch it and the Deploy entry guard can hold it back, not in the response a student gets when they open a page; the L-003 rule against chatbot framing applies here at full strength. Evidence: evidence-08-static-site-not-chatbot. Inferential move: this is the architectural contrast the workplan's annotated bibliography names with Sajja et al. (2023) and that Section XII develops with the Magesh et al. hallucination findings; Section VIII names the choice and points forward, so Section XII can land its risk argument on a posture the article has already established. [evidence: evidence-08-static-site-not-chatbot]
