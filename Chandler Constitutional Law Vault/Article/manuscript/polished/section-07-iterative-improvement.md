# VII. Iterative Improvement Under Professorial Control

## A. The Karpathy loop, domesticated

On March 7, 2026, Andrej Karpathy released `autoresearch`, a Python script that delegates the modify, run, evaluate, keep-or-discard loop to a language-model agent and that ran fifty experiments overnight to surface a learning-rate improvement.[^1] The structural insight the script makes legible is four-piece: a per-phase rubric that scores each pass on criteria the phase owns, a lessons file that carries durable memory between passes, a rolling scorecard that records what each pass produced, and a forced-finding adversarial pass that has to return findings rather than confirm everything looks fine. The vault adopts the architecture and not the autonomous-agent setting that runs it. Karpathy’s loop runs unsupervised against a measurable scientific objective; the vault’s loop runs against a non-measurable pedagogical objective, with the professor available to gate, defer, redirect, or reverse any phase, and with reviewer comments preferred over the rotation’s own next-in-queue work. The structural insight imports because it makes generation reviewable; the autonomous-agent execution does not import because the article’s central claim is that professorial judgment is what the loop is in service of, not what the loop replaces.

## B. One phase per tick: the rotation as the loop

The vault’s maintenance rotation runs through six phases (Ingest, Lint, Enrich, Expand, Synthesize, Verify) and then repeats.[^2] Each scheduled-task tick selects one active phase from that sequence, executes the procedure for that phase once, writes the resulting state, and advances the next-phase pointer for the following tick. An autonomous Karpathy-style loop touches every phase in a single overnight pass; the vault commits one phase per tick and lets the rotation itself be the loop. The choice keeps each pass small enough for the professor to inspect on its own terms, lets each phase’s quality differ instead of being averaged into a single per-pass number, and gives each phase a separate scope-selection step that can prefer professorial input over the rotation’s own next-in-queue work.

## C. The forced-finding Verify pass: catching what other phases let pass

The Verify phase runs three hostile personas (Staleness Auditor, Contradiction Hunter, Template Enforcer); each must return at least one concrete finding per run, and a persona that genuinely finds nothing records *persona-produced-nothing* as its own finding so the absence of findings is auditable.[^3] A lead-rotation table and a per-persona focus-mutation table both keyed off the Verify run count reshape the lead-and-focus pairing every pass. The forced-finding rule converts Verify from a phase that confirms things look fine into a phase that catches what prior phases missed.

The *Prize Cases* (1863) is the canonical iteration story.[^4] Ingest pulled a Justice Grier quotation from the professor’s modernized PDF, and the language read clean on its face. Midpage’s `findInOpinion` returned zero results when asked to verify, and the zero was logged as an OCR artifact and left alone. The corrupted quotation propagated from the brief to the War Powers topic page. Several runs later, a Verify persona was specifically told not to accept zero results as an answer and switched from keyword search to `analyzeOpinion`; Midpage returned Grier’s actual language. The vault had said “never formally declared…by its character.” Grier wrote “never solemnly declared…by its accidents.” The correction was grep-driven back across the vault to catch the stale copy on the topic page. The error had run through Ingest, Lint, two Enrich passes, and Expand before Verify caught it.

A second iteration story shows the same loop catching a different type of error. The Judicial Votes section of the *Youngstown* brief first read that Frankfurter, Douglas, Jackson, and Burton all “joined” Black’s majority. The shorthand is defensible but misleading for a law student, because *Youngstown*’s six-justice majority produced six separate opinions, with two justices joining the opinion and also writing separately and three concurring in the judgment only.[^5] The brief sat partially wrong through several cycles because no prior phase was looking for the mischaracterization. The Contradiction Hunter persona on a focus-area pass dedicated to concurrence-versus-majority mischaracterization triggered an `analyzeOpinion` re-check of Frankfurter’s actual language and produced the rewrite. Two iteration stories broaden the failure-mode coverage from quotation-text errors to doctrinal-characterization errors.

## D. Loop memory: LESSONS as durable record, scorecard and narrative as audit trail

The vault’s `LESSONS.md` is the loop’s running memory.[^6] Every run that catches an error or notices a pattern appends a fixed-schema entry (Rule, Why, How to apply, an optional dated Seen footer). The file is capped at thirty-five entries, and an out-of-rotation Consolidate sweep merges duplicates and prunes superseded entries so the cap stays honest rather than aspirational. Loading is tiered: Ingest, Enrich, Expand, and Synthesize read the file because they generate content; Lint and Verify skip it because the corrections that govern structural checks differ from the corrections that govern content. The lessons file is what answers a reader who asks whether the loop is improving or just running.

The token-problem story shows the loop reshaping its own architecture rather than catching a content error.[^7] Early runs loaded one large `RUBRIC.md` covering all six phases, the full `LESSONS.md`, and the entire build narrative every pass, so a Lint run that only cared about structural formatting was burning context on Enrich and Verify criteria it would never use. The fix was tiered loading (per-phase rubric files, LESSONS skipped by Lint and Verify, build narrative rotated monthly, no-op phases stopped being scored); a secondary fix fell out of the same change, because the shared rubric had let one phase game a criterion in a way that made its own score look good and another phase’s job harder. The per-phase-rubric-only principle is the article’s own L-007.

The run-by-run scorecard at `.run-scores.jsonl` and the rolling `BUILD_NARRATIVE_YYYY-MM.md` are the loop’s audit trail.[^8] The scorecard holds one JSON line per run containing the active phase, the weighted criteria scores, the red-flag list if any, and the timestamp. The narrative holds a two-to-four-sentence prose entry per run describing what the phase did and what was learned. The two artifacts together let a reviewer reconstruct the loop’s state at any past moment: the scorecard for measurable phase quality, the narrative for the structural context the score alone cannot carry.

## E. Professorial control: the page-feedback intake and the staging triplet

The vault’s answer to professorial control is the page-feedback intake at Step 0 of every scheduled-task run.[^9] Before the phase dispatcher selects the active phase, Step 0 pulls inbound comments from the deployed-site page-feedback form, triages each submission into one of six routes (trivial fix, structural, analytical, cross-reference, topic-level, verification), and logs a typed *professor-feedback* pending issue routed to the phase that owns the fix. Trivial fixes land on the same run; structural and substantive feedback waits for the phase that owns the fix to rotate around, and that phase’s scope-selection step must prefer pages carrying open *professor-feedback* issues routed to it. The intake is the architectural feature that distinguishes the vault’s loop from a Karpathy-style autonomous loop. The staging triplet is its observable counterpart: *Trump v. United States* sits at the skeleton stage, with the factual sections filled and the rest marked by `<!-- ENRICH: -->` stubs; the Rehnquist Court Commerce Clause lecture covering *Lopez* and *Morrison* is mid-cycle, mostly clean with a handful of stubs marking places to go deeper; *Gonzales v. Raich* is a case after a full Enrich cycle, with majority analysis, Scalia’s concurrence, O’Connor’s and Thomas’s dissents, five hypotheticals, critique from both directions, and every Key Quotation pin-cited against Midpage.[^10] The system did not replace professorial judgment; it made that judgment reusable, inspectable, and publishable.
